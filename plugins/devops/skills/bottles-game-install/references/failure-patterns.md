# Measured failure patterns

These were observed with Bottles 67.2 / Soda 11.0-9 in September 2026. Confirm versions and the actual symptom before using them. Consult the local diagnosis for raw artifacts; do not generalize a successful retry into a proven root cause.

- **Missing ISArcExtract files:** a document-portal path exported setup.exe alone. Exposing the real installer directory and launching there restored neighboring archives. A destination change cannot fix missing source files.
- **False insufficient space:** Z: mapped to the Flatpak root tmpfs; C: mapped to the prefix on a much larger SSD. Inspect dosdevices and filesystem capacity inside the app, plus the host prefix filesystem. Do not remap Z: globally; Wine and Bottles may use it for legitimate absolute paths.
- **Black window / repeated Quit or Wait:** strace and gdb found Wine X11 `wait_grab_pointer` looping on XGrabPointer AlreadyGrabbed with 10 ms sleeps. Native Wayland bypassed that path; an isolated Xvfb display also allowed installation. Neither is a universal extraction fix. Native Wayland may lack ordinary launcher decorations; verify usability on the real desktop. Source: https://github.com/ValveSoftware/wine/blob/bleeding-edge/dlls/winex11.drv/event.c
- **Controller initialization crash:** the affected builtin xinput1_4.dll called `strcmp(getenv("SteamGameId"), "298110")` without a null check. Disassembly and the null-pointer backtrace established it. A bottle-local `SteamGameId=0` prevented that specific crash. Check for a fixed runner first; do not override a real Steam game's environment. Do not infer this defect solely from a generic XInput error.
- **Extraction failure around 0.9%:** memory allocation warnings, stack overflow and a lock timeout occurred even with a verified 2 GB limit. The implicated archive checksum was valid; a later run succeeded with no decompressor modification. Exact trigger remained unresolved. Do not label it corrupt data, fixed by the checkbox, or the same defect as the X11 hang without new evidence.
- **NVIDIA warning:** NVAPI disabled and vendor spoofing coincided with failed GPU detection. Installing/enabling matching dxvk-nvapi in both bottle and saved program resolved that launch stage. Changing a boolean alone did not install DLLs. Missing optional nvcuda/DLSS frame-generation support is a separate issue, not automatically the crash cause.

An installed official Flatpak update associated with Bottles 67.3 corrected folder-opening and runtime compatibility issues; package metadata still displayed 67.2. Verify commit/runtime and live behavior, not just the marketing version. These release notes do not prove the above Wine defects are fixed: https://github.com/bottlesdevs/Bottles/releases/tag/67.3
